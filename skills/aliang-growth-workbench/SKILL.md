# Aliang-Growth-Workbench

帮助用户建立属于自己的个人系统，让日常资料可找到、可复用、可持续维护。先读取用户指定位置的现状和适用规则；已有工作台优先沿用，不覆盖或重复初始化。

## 建立工作台

技能发布仓库仅用于获取本技能；用户工作台必须建立在使用者自己选择和拥有的本地目录及其本人授权的私有仓库中，不克隆、复制或写入技能作者的个人工作台及个人数据。

1. 主动向用户解释推荐方案：GitHub 私有仓库作为备份，本地克隆后日常使用；Git 和 GitHub 分别检查，不假定已安装、已登录或允许联网。用户不希望使用 GitHub 时，直接提供本地方案，不强迫注册或安装。
2. 帮用户选择本地位置与仓库名：先检查现有工作区、合理的目录及同名冲突，给出一个具体建议和用途；用户没指定且不能安全推断时询问。不要默认扫描电脑、聊天、云盘或私人目录。
3. 用户选择 GitHub 方案时，先向用户列出具体账号、私有仓库名、本地路径、将生成及可能上传的内容，并在创建远程仓库、初次提交或推送前分别遵循明确授权与客户端规则。不要让私有仓库变为公开；Git 凭据由现有安全机制处理，不记录或输出令牌。没有 gh、未登录、权限不足或无法确认仓库私有时说明原因并保留本地方案，不自行安装、登录、变更配置或反复重试。
4. 创建或选择已明确授权的空私有远程仓库，克隆到指定的新本地目录；校验远程确为私有且为空。对于已有非空仓库，先检查并提出合并方案，绝不覆盖。先说明同步范围和隐私，让用户决定是否同步个人记忆：默认运行 `python3 <本技能目录>/scripts/init_workbench.py --root <本地路径>`；用户明确选择同步个人记忆时追加 `--sync-memory`。脚本仅接受新目录、空目录或仅含 `.git` 且无提交和暂存内容的空仓库。重复运行对已有工作台只校验并刷新，不改变已有同步规则。
5. 新工作台默认允许收件箱、项目和归档内容纳入 Git 跟踪；个人记忆默认忽略（README 除外），使用者可选择同步。允许跟踪不代表已经提交、推送或备份。收件箱、项目、归档、知识库及能力库也可能包含私人资料；首次提交和推送前说明私有仓库的可访问者及 Git 历史留存风险，逐项检查暂存内容、实际忽略规则和远程私有性，按用户选择排除不愿上传的资料。常见凭据文件默认忽略，但这不能保证发现所有秘密；不得提交密钥或密码。首次提交和推送仅在获得相应授权后执行，不自动上传既有用户资料。已有工作台只在用户授权后调整其 .gitignore，不自动改写已跟踪或已推送的资料。
6. 本地方案同样运行初始化脚本，指定新目录或空目录；将来用户需要时再连接私有 Git。初始化成功后报告本地路径、远程地址和隐私状态（若有）、实际提交推送状态、同步范围和未完成事项。原则由使用者依据自己的需求决定和补充。

## 整理与维护

- 新建记忆库的入口规则要求 AI 对实际任务按需发现并读取相关记录，完成后判断并整理可复用经验；这依赖客户端加载该入口及文件访问权限，不是后台监听。用户确认的事实与候选经验分开，不把推测写入个人记忆，不自动提交或推送。已有记忆库的入口不会因升级自动改变，先检查现状并在明确授权后合并规则，不覆盖原有内容。
- 规则管理通用原则；记忆记录用户确认的个人事实和事件；知识保存理解后值得复用的观点、方法和案例；能力管理工具与方法的发现、评估、验证、使用和退役；收件箱收集灵感和待办；项目管理执行；归档保存不再活跃但有保留价值的内容。
- 用户指定资料或范围后先检查并区分原始资料、用户事实和 AI 判断，按用途整理；明确来源与不确定性。避免重复内容与覆盖并发修改；删除、发布、外部写入和高影响变更遵循用户授权。涉及长期个人记忆时区分明确事实与推断，不能把猜测写成事实。
- 评估能力时比较解决的问题、实际增量、来源许可、依赖、权限、成本、验证及回退。单独记录管理状态、健康、安装位置与等级。静态检查不代表真实任务通过。发现成熟方法时，提炼可复用知识并注明来源及验证程度。
- 用户要求盘点 skill 时，只读用户指定目录；不指定时先说明拟检查范围并据已有授权选择，禁止扫描凭据或执行未知代码。读取入口和必要支持文件，报告用途、重复、状态、风险与真实验证缺口；安装存在不等于验证通过。只有在用户要求登记时才按工作台规则建立候选记录，记录实际安装证据，不猜测是否启用。
- 按生成工作台的 `AGENTS.md` 更新能力正式记录，再运行 `python3 <工作台>/04-能力库/系统文件/自动化程序/刷新能力视图.py`。索引和分类视图由脚本生成；发现匹配不代表授权执行。操作后报告实际结果和未验证事项。

## 分享与隐私

分享本技能时只分享本技能目录；不包含使用者生成的工作台、个人资料、凭据、原始素材或日志。内附第三方能力管理代码，遵守其 LICENSE 并保留版权声明。不要擅自发布；向其他客户端安装或配置前核对其实际支持情况。更详细的录入与状态规则按需阅读 [能力管理](references/capability-management.md)。
